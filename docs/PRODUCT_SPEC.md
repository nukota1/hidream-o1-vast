# Product Specification

最終更新: 2026-07-31 (JST)

## 1. 製品の目的

本サービスは、ギャルゲー・ADV・ライトノベル向けの立ち絵とイベントCGを、日本語の自然言語から生成・再編集するためのイラスト制作環境である。

優先順位は次の通り。

1. 背景、表情、ポーズを変えても、同じキャラクターとして認識できること
2. 人物属性と変更指示へのプロンプト追従性が高いこと
3. 自動マスク由来の背景縁、透過、髪の欠損を標準フローからなくすこと
4. キャラクターを再利用可能な資産として保存し、将来のADV・ライトノベル制作ツールから利用できること

## 2. 基本概念

- キャラクター定義: 髪、目、年齢感、体格、衣装、装飾品など、カットをまたいで維持する人物属性
- シーン指示: 背景、時間帯、天候、照明、カメラ、表情、ポーズなど、カットごとに変える属性
- Character LoRA: 複数の採用画像から人物固有の特徴を学習した、長期的な同一性の正本
- Style LoRA: 複数人物・複数シーンに共通する線画、塗り、色設計を学習した、再利用可能な画風の正本
- 参照画像: IP-Adapter Plusで現在の生成だけに外見を補強する画像
- 一貫再生成: キャラクター定義、LoRA、参照画像、新しいシーン指示を使い、背景を含む一枚絵を全画面で再生成する処理
- 手動局所修正: ユーザーが指定したマスク範囲だけをWaifu-Inpaint-XLで修正する上級機能

## 3. 日本語プロンプト最適化

ユーザーは人物とシーンを日本語の自然言語で入力できる。カタログ入力は補助情報として扱い、自由入力を優先する。

Qwenで人物とシーンを別々にモデル向け英語タグへ変換し、次の優先順で統合する。

1. 人数と主体（例: `1girl, solo`）
2. Character LoRAトリガーと固定人物定義（髪、目、顔、体格）
3. Style LoRAトリガー
4. 今回変更する表情、ポーズ、構図
5. 衣装、カメラ、シーン、背景
6. 画風、品質

最適化後の人物、シーン、統合プロンプト、処理意図はメタデータへ保存する。背景変更時は元画像のシーンタグを負の条件へ移し、以前の背景を引きずりにくくする。

## 4. 新規生成

### 4.1 キャラクター素材

背景・シーンを指定しない場合は、白い無地背景のキャラクター確認用画像を生成する。これは採用画像の選定、LoRA学習、参照画像の起点に使う。

標準生成時に人物抽出、クロマキー化、輪郭マスク生成は行わない。

### 4.2 ADV・ライトノベル用の一枚絵

人物入力とシーン入力を別々に最適化した後、一回のSDXL生成で人物と背景を同じ光、色、遠近、接地影の中に描く。

背景だけを後段inpaintする自動二段階方式は使用しない。人物と背景の境界をマスクで分離しないため、クロマ境界やマスク残りは標準経路では発生しない。

### 4.3 複数候補の逐次生成

新規生成と一貫再生成では、1回の操作で1〜8枚を指定できる。GPU処理は並列化せず1枚ずつ順番に実行し、完成した画像から結果画面へ追加する。

同じ画風と構図意図を保つため、バッチ内では人物・シーンprompt、LoRA、画風、サイズ、Steps、CFG、Sampler、Clip Skipを共通にする。1枚目は入力Seedを使い、2枚目以降だけ重複しないランダムSeedへ変更する。

複数結果はSeed付き一覧で表示する。選択中の画像を、ダウンロード、R2保存、一貫再生成の対象として扱う。

## 5. 一貫再生成

背景、表情、ポーズ、カメラ、構図を変更する場合も、元画像の人物画素を切り抜かず、背景を含む一枚絵として再生成する。

使用する条件は次の通り。

- Character LoRA: 長期的な顔、髪、体格、デザインの再現
- Style LoRA: キャラクター間で共有する線画、塗り、色設計
- IP-Adapter Plus: 選択した一枚の外見を即時に補強
- キャラクター定義: 維持すべき人物属性
- シーン指示: 今回変更する背景、表情、ポーズ、構図
- Seedと生成設定: バリエーションの再現

参照画像は、旧背景の影響を減らすため人物中心部を切り出して使用する。既定参照強度は25%とし、人物維持を強めたい場合は30〜35%、新しいポーズ・構図への追従を優先する場合は20〜25%を目安とする。

IP-Adapterの強度を上げるほど元画像の外見と構図を維持しやすく、下げるほど新しい指示へ追従しやすい。LoRAは人物同一性を高めるが、元画像のピクセルやポーズを固定する機能ではない。

ギャラリー、結果画面、拡大画面から、画像、人物定義、シーン履歴、LoRA、生成設定を一貫再生成画面へ引き継げる。

画風の4つの強度はブラウザに保存し、画面の再読み込み後も維持する。生成時にもメタデータへ保存し、「プロンプトを履歴から参照」では人物・シーン入力と同時に生成時の画風強度を復元する。

## 6. 厳密なポーズ制御

テキストとIP-Adapterだけでは、「顔元でピース」のような手指を含むポーズを毎回保証できない。厳密なポーズ指定にはOpenPose ControlNetを追加し、次のいずれかを入力にする。

- ユーザーが用意したポーズ参照画像
- アプリ内のポーズテンプレート
- 将来のADV制作ツールから渡される骨格情報

OpenPoseは骨格と手の配置、LoRAは人物同一性、IP-Adapterは外見、テキストは表情・背景・演出を担当する。役割を分離し、各強度を独立調整できるようにする。

## 7. Character LoRAとStyle LoRA

ギャラリー画像の右クリック、長押し、メニューボタン、拡大画面から「このイラストで追加学習する」を選択できる。

学習画面では次を指定する。

- LoRA名
- トリガーワード
- 人物の固定定義（日本語可）
- 人物の固定除外条件（例: `side bun, bun beside ear`）
- カテゴリ
- モデルタイプ
- 学習画像
- 学習ステップまたは推奨設定

一枚学習は試験用途として許可するが、実用的なキャラクターLoRAには、同一人物で角度、表情、ポーズ、照明、背景が異なる10〜20枚を推奨する。背景・衣装が全画像で固定されるとLoRAへ混入するため、変化を持たせる。

学習画像ごとに、衣装、背景、ポーズ、表情をcaptionとして保存する。人物固有の顔、髪、目、装飾はトリガーワードへ学習させ、生成時は人物定義でも補強する。縦長画像は全身を切らないアスペクト比バケットを使用し、左右非対称の特徴を守るためCharacter LoRAではランダム左右反転を既定で行わない。

人物の固定定義はLoRAメタデータへ保存し、そのLoRAを選択した生成では人物入力の前に自動挿入する。固定定義とユーザーの変更指示は短いモデル向けタグへ変換し、CLIP上限では画風の装飾語より人物属性とポーズを優先する。

人物の固定除外条件と、学習セット全体で固定された白背景などはモデルメタデータへ記録する。生成時にユーザーが要求していない要素はnegative promptへ追加し、誤った髪型、体格、背景、衣装の過学習を抑える。

Style LoRAはCharacter LoRAから分離する。単一人物だけで学習せず、同じ画風で人物、髪、衣装、ポーズ、背景、構図が異なる画像を50枚以上推奨する。既定はrank 32、学習率 `5e-5`、左右反転あり、推論強度0.6とする。Character LoRAは既定rank 16、学習率 `1e-4`、左右反転なし、推論強度0.8とする。

ローカルとVast.aiの学習・推論基盤は `sdxl-animagine-zero` に統一する。LoRAメタデータには正確な基盤モデルprofileを保存し、旧Animagine OptまたはJANKU用LoRAはZeroへロードしない。

学習は生成と同じGPUロック内で直列化し、進捗をSSEで返す。状態は `queued`、`training`、`ready`、`failed` として保存し、完成した互換LoRAをカテゴリ別に選択できるようにする。Character LoRAとStyle LoRAは同時にロードし、強度を独立設定する。

## 8. 手動局所修正

Waifu-Inpaint-XLは、目、口、手、装飾など、ユーザーが明示した局所だけを修正する上級機能として残す。

- ユーザーが編集範囲をマスクで指定する
- マスクがない場合は局所修正を開始しない
- 自動人物抽出、クロマキー、背景輪郭マスクは使用しない
- 背景、表情、ポーズの標準的な変更は一貫再生成を使う

## 9. 保存する資産

将来のADV・ライトノベル制作ツールで再利用できるよう、次を保存する。

- キャラクター定義とトリガーワード
- Character LoRAと適用強度
- Style LoRAと適用強度
- 参照画像と参照強度
- 完成画像
- 人物、シーン、統合後の各プロンプト
- 元シーン、変更指示、処理意図
- モデル、Seed、生成設定
- 画風の4つの強度
- 変更履歴

## 10. 現時点の非対象

- 複数GPUへの分散学習
- 学習ジョブの外部キュー
- LoRA重みのR2バックアップと複数Vast.aiインスタンス間同期
- 複数参照画像の同時入力
- FaceID、Depth ControlNet
- ネイティブな透過レイヤー生成
- 自動キャプションの人物属性とシーン属性の完全分離
