# Project Status

最終更新: 2026-07-29 (JST)

## 現在の目標

ギャルゲー・ADV・ライトノベル向けに、背景、表情、ポーズを変えてもキャラクターの一貫性を保ち、人物属性と変更指示への追従性が高い一枚絵を生成する。

## 現在の標準アーキテクチャ

- ローカルとVast.aiの基盤モデルをAnimagine XL 4.0 Zeroへ統一する
- 日本語の人物定義とシーン指示をQwenで別々に最適化する
- 人数、今回の変更、人物属性、シーンの順にタグを優先してSDXLへ渡す
- 新規の一枚絵は人物と背景を一回の全画面生成で描く
- 一貫再生成はCharacter LoRA、Style LoRA、IP-Adapter Plus参照、人物定義、新しいシーン指示を同時に使う
- IP-Adapter参照は人物中心にクロップし、旧背景の影響を減らす
- 背景変更時は元シーンのタグを負の条件へ移す
- 自動人物抽出、クロマキー、輪郭マスク、背景inpaintは標準UIから外す
- Waifu-Inpaint-XLはユーザー指定マスクによる局所修正だけに使用する

## 既知の制約

- テキストとIP-Adapterだけでは、顔元のVサインなど手指を含む厳密なポーズを毎回保証できない
- 今回の30枚は白背景と同じ衣装で統一されているため、トリガーワード単独より人物定義との併用が安定する
- 正しい固定人物定義で目色と顔年齢は改善したが、脚の長さ・身長比率は元画像より高くなる場合があり、v2の体格再現は未達
- 生成画風はCharacter LoRAよりローカル基盤モデルAnimagine XL 4.0の影響が強く、学習画像と同じ画風を保証しない
- v3でも画風は学習画像へ近づくがAnimagine XL 4.0の影響が支配的であり、他キャラクターと画風を揃えるにはStyle LoRAが必要
- v3の髪型教師画像には正面・斜め向きでお団子が側頭部へ突出している画像が含まれ、Zeroへそのまま再学習すると誤配置を強化する
- 旧v2・v3はAnimagine Opt用であり、Zero向けCharacter LoRAを再学習するまで新基盤では使用しない
- Style LoRA用の複数人物・複数背景データは未準備のため、画風学習は未実施
- 600・800ステップ版は400ステップ版より脚が長くなり、猫型髪飾りがお団子側へ寄る傾向があるため既定採用しない
- 長い固定人物定義とシーンを結合した実API生成では、`seaside train station, ocean, sunset`が最終promptで一般的な屋外タグへ縮約された。シーン固有タグの保持はT-018で修正する
- LoRA＋参照25%は外見維持が強い一方、元ポーズや靴の要素を少し引き継ぐ。ポーズ優先時は参照20%を推奨
- 最新コードのVast.ai起動とCloudflare Worker・R2・D1を含むend-to-end検証は未実施
- Vast.ai側でPython/CUDA依存を永続ディスクへ保存するか、依存込みイメージとの起動時間・転送量を比較する必要がある
- 旧クロマ・人物抽出コードは既存資産と手動処理の互換用に残っているが、標準UIからは実行しない
